# AUST 校园认证助手 · Android 打包部署指南

手机端源码已在本仓库 `phone/` 目录（Capacitor 6 + 已提交的 `android/` 工程），
克隆仓库后直接同步、编译即可，**不需要再执行 `npx cap add android`**。

---

## 本机已验证的环境

| 工具 | 版本 | 说明 |
|------|------|------|
| Node.js | >= 18 | https://nodejs.org |
| JDK | 17；或 Android Studio 自带 JBR 21（`JAVA_HOME` 指向它） | 命令行构建依赖 `JAVA_HOME` |
| Gradle | wrapper 8.7（腾讯镜像） | 无需单独安装，用 `android/gradlew` 即可；镜像地址见 `android/gradle/wrapper/gradle-wrapper.properties` |
| Android SDK | platform-34 + build-tools-34 | 通过 Android Studio SDK Manager 安装 |

Android Studio 安装后，在 **SDK Manager**（右上角齿轮图标）里勾选：

- Android SDK Platform **34**
- Android SDK Build-Tools **34.x**
- Android SDK Command-line Tools（latest）

环境变量（Windows）：

```
ANDROID_HOME = C:\Users\你的用户名\AppData\Local\Android\Sdk
Path 中添加：
  %ANDROID_HOME%\platform-tools
  %ANDROID_HOME%\cmdline-tools\latest\bin
```

## 构建步骤

```bash
cd phone

# 安装前端依赖（慢的话见「常见坑」第 3 条）
npm install

# 把 www/ 同步进 android 工程（改过 www/index.html 后都要执行）
npx cap sync android

# 命令行编译 debug APK
cd android
./gradlew assembleDebug        # Windows CMD/PowerShell 下用 gradlew.bat assembleDebug
```

产物：

```
phone/android/app/build/outputs/apk/debug/app-debug.apk
```

如果命令行找不到 JDK，可显式指定（Android Studio 自带的 JBR）：

```bash
JAVA_HOME="D:/AndroidStudio/jbr" ./gradlew assembleDebug
```

### 用 Android Studio 构建

```bash
npx cap open android
```

或直接用 Android Studio 打开 `phone/android/`，等待 Gradle 同步完成，然后
**Build → Build App Bundle(s) / APK(s) → Build APK(s)**，点提示框里的 **locate** 找到 APK。

## 安装到手机

```bash
# 手机开启 USB 调试后连接电脑
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

也可以把 APK 传到手机，用文件管理器安装（需允许「安装未知来源应用」）。

## 发布正式版（签名，可选）

keystore **不在仓库里**，需要自己生成并妥善保管（注意：`phone/android/.gitignore` 中
`*.jks` / `*.keystore` 的忽略规则默认是注释状态，可在本地取消注释，或把 keystore 放到仓库目录之外）。

在 Android Studio 中：

1. **Build → Generate Signed Bundle / APK**
2. 选择 **APK** → 创建或选择签名 keystore
3. 选择 **release** 构建类型
4. 编译出 `app-release.apk`，体积更小，可正常分发

命令行签名同理：在 `android/app/build.gradle` 中配置 `signingConfigs`（引用本地 keystore 路径），
再执行 `./gradlew assembleRelease`。注意不要把 keystore 和密码提交进仓库。

## 常见坑

1. **中文/非 ASCII 路径**
   仓库路径含中文（如 `F:\kakuns开源项目\AUST`）时，Windows 下 Gradle 会有路径警告。
   本工程已设置 `android.overridePathCheck=true`（在 `phone/android/gradle.properties`，**勿删**）绕过；
   本项目没有 NDK/JNI 原生代码，该绕过是安全的（`gradle.properties` 里也有同样注释）。

2. **Gradle 发行包走腾讯镜像**
   `gradle-wrapper.properties` 中的 `distributionUrl` 指向
   `https://mirrors.cloud.tencent.com/gradle/gradle-8.7-bin.zip`。
   如镜像不可达，可改回 `https://services.gradle.org/distributions/gradle-8.7-bin.zip`，或换用其他镜像。

3. **npm 依赖安装慢**
   使用镜像：
   ```bash
   npm install --registry=https://registry.npmmirror.com
   ```

4. **网络安全配置（HTTP 明文）已随 `android/` 提交**
   `android/app/src/main/res/xml/network_security_config.xml` 与 `AndroidManifest.xml` 中的
   `android:networkSecurityConfig` / `android:usesCleartextTraffic` 都已在仓库里，
   **无需再手动复制配置**（`phone/android-network-security-config.xml` 只是历史备份，可不用）。
   DrCOM 认证服务器走 HTTP，删掉这项配置会导致请求被系统拦截。

## 常见问题

**Q: 还需要 `npx cap add android` 吗？**
A: 不需要。`android/` 工程已提交在仓库里；只有从零重建工程时才需要执行它。

**Q: `npx cap sync android` 报错 / 网页内容是旧的**
A: 确认在 `phone/` 目录执行，并且 `www/index.html` 改动已保存；同步后再重新编译 APK。

**Q: Gradle 下载超慢**
A: 见「常见坑」第 2 条（wrapper 走腾讯镜像）。若卡在依赖仓库，可在
   `android/build.gradle` 里换成国内 Maven 镜像：
   ```
   maven { url 'https://maven.aliyun.com/repository/google' }
   maven { url 'https://maven.aliyun.com/repository/central' }
   ```

**Q: DrCOM 认证还是失败**
A: 确认手机已连接校园网（WiFi 或有线热点），然后在应用日志里看具体报错。
   HTTP 明文流量依赖仓库里已提交的网络安全配置，若被误删请求会被 Android 系统拦截。

**Q: 验证码图片显示不出来**
A: Portal 登录需要 HTTPS，确认 `xgmm.aust.edu.cn` 可访问。
   图片通过 `CapacitorHttp.get + responseType: arraybuffer` 获取后转 base64 显示，
   不依赖 WebView 跨域。

**Q: 想修改 UI / 添加功能**
A: 直接编辑 `phone/www/index.html`，然后 `npx cap sync android`，再重新编译 APK 即可。
